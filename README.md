# Lik31 Android

Lik31 確定性密碼產生器的 Android 版。演算法與瀏覽器套件
「Lik31 Password Generator」3.0.0 相同，同樣的主密鑰與服務金鑰會得到同樣的密碼。
操作方式延續舊的 MS Password Generator：開啟即出現對話框與鍵盤，點一下密碼就複製並關閉。

## 使用方式

- 從 App 圖示或快速設定方塊開啟（方塊需先在快速設定的編輯畫面手動加入）。
- 輸入主密鑰與服務金鑰，密碼即時顯示。
  - 點一下密碼（或按鍵盤的完成鍵）即複製並關閉。
  - 長按密碼時，密碼區會交替顯示「放開即複製並關閉」與密碼；放開即複製並關閉，手指滑出密碼區再放開則取消。
- 密碼區固定兩行高，由程式依寬度自行斷行（第一行放滿），兩行放不下時字型由 20sp 逐步縮到 14sp，仍放不下才出現第三行。
- 複製時會記住這個服務的長度與符號，下次輸入同一個服務金鑰時自動套用（服務金鑰欄出現循環箭頭圖示）。
- 主密鑰欄右側的手機圖示是「儲存主密鑰於此裝置」開關。打開後，之後開啟會直接從服務金鑰開始輸入。
  - 儲存的是主密鑰的雜湊，以 Android Keystore 中的 AES-256-GCM 金鑰加密，不會進入備份或裝置轉移。
  - 已儲存時欄位留空＝使用已儲存的主密鑰（只有雜湊，不顯示圓點，也不能顯示內容）。
  - 輸入內容＝本次改用輸入的主密鑰，標籤變為「將取代已儲存」，複製密碼時取代已儲存的；圖示上的黃點代表「複製時寫入」。
  - 關閉開關會先確認，確認後刪除已儲存的資料與金鑰。
- 生物辨識保護（Android 9 以上、裝置已登錄高強度生物辨識時自動啟用）：
  - 儲存時不需要驗證；開啟 App 時跳出系統的生物辨識畫面，通過後才能使用已儲存的主密鑰。
  - 選「改為輸入主密鑰」或取消時，可以直接輸入主密鑰，僅本次使用、不會覆蓋已儲存的；欄位右側的開鎖圖示可再次解鎖。
  - 鎖定且未輸入主密鑰時不會產生密碼。
  - 新增或刪除指紋後，已儲存的主密鑰會失效並被清除，需要重新輸入並儲存。
  - 先前以舊方式儲存的主密鑰，會在下一次開啟時自動升級為生物辨識保護，再下一次開啟起需要驗證。
- 設定頁（卡片右上角的齒輪圓鈕）：
  - 預設長度：用於沒有記錄的服務，下次開啟產生器時生效。
  - 以生物辨識保護已儲存的主密鑰：關閉後，下一次開啟並解鎖時改為不需驗證的方式保存；重新開啟後，下一次開啟時自動轉回保護。
  - 禁止截圖：回到產生器時立即生效。
  - 已記住的服務設定：顯示數量，可全部清除。
  - 快速設定方塊（Android 13 以上）：請系統跳出「加入方塊」的詢問。
  - 關於：演算法、自我檢查結果、版本。
  - 從設定頁按返回會回到產生器；從設定頁離開 App（回桌面等）則連同產生器一起關閉。
- 警告以標籤與顏色表示，不阻擋操作、不改變版面高度：
  - 主密鑰為空卻產生了密碼 →「主密鑰・空白」；
  - 服務金鑰前後有空白 →「服務金鑰・含前後空白」；
  - 長度 12 以下 → 長度數字與圖示變色。
- 離開畫面（回桌面、切換 App、關螢幕）即關閉並清除輸入中的內容。

## 建置

需要 JDK 17 以上與 Android SDK（API 36）。用 Android Studio 開啟專案資料夾，或：

```
./gradlew :core-lik31:test :app:testDebugUnitTest   # 單元測試
./gradlew :app:assembleDebug                        # 產生 app/build/outputs/apk/debug/app-debug.apk
```

推送到 GitHub 後，`.github/workflows/ci.yml` 會自動跑測試並把 debug APK 存成 artifact。

## 更新比對資料

瀏覽器套件改版時，以新版覆蓋 `tools/gen-vectors/popup.js`，然後：

```
node tools/gen-vectors/gen-vectors.mjs
```

CI 會檢查已提交的 `golden-vectors.json` 與重新產生的結果一致。

## 與瀏覽器版的行為差異（都不影響產生的密碼）

- 服務金鑰為空時不顯示密碼（瀏覽器版會產生一組）。
- 符號欄只接受一個 BMP 字元；emoji 與控制字元會被拒絕（瀏覽器版會插入半個代理對，產生亂碼）。
- 主密鑰為空且沒有已儲存的主密鑰時，照樣產生密碼，與瀏覽器版一致，並以標籤提示。
- 每個服務除了長度，也記住符號（瀏覽器版只記長度）。記錄在複製密碼時寫入。
- 已儲存主密鑰時清空主密鑰欄，代表使用已儲存的主密鑰（瀏覽器版會把空字串的雜湊存起來覆蓋掉）。
- 新輸入的主密鑰在複製密碼時才取代已儲存的（瀏覽器版每打一個字就覆蓋一次）。空的主密鑰不會被儲存。
