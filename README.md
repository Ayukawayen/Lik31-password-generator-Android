# Lik31 Android

Lik31 確定性密碼產生器的 Android 版。

用一組只有你知道的**主密鑰**，加上每個網站或服務各自的**服務金鑰**（例如網域名稱），每次都算出同一組密碼。密碼不儲存、不同步，也不需要網路。

演算法與瀏覽器套件「Lik31 Password Generator」3.0.0 相同：同樣的主密鑰與服務金鑰，在手機和瀏覽器上會得到同樣的密碼。

## 特色

- **開啟就能輸入**：以對話框形式浮在目前畫面上，鍵盤同時開啟；點一下密碼就複製並關閉。
- **快速設定方塊**：可從通知列的快速設定直接開啟。
- **記住每個服務的設定**：長度與符號在複製時記下，下次輸入同一個服務金鑰時自動套用。
- **可選擇儲存主密鑰**：只儲存雜湊，以 Android Keystore 加密，並可用生物辨識保護。
- **不要求任何權限**：不連網，資料不進入備份或裝置轉移。
- **離開即清除**：回桌面、切換 App 或關閉螢幕時，畫面立即關閉並清除輸入中的內容。

## 系統需求

- Android 8.0（API 26）以上。
- 生物辨識保護需要 Android 9 以上，且裝置已登錄高強度生物辨識（例如指紋）。
- 由 App 請系統加入快速設定方塊需要 Android 13 以上；較舊的版本可在快速設定的編輯畫面手動加入。

## 安裝

目前沒有上架商店，也沒有正式簽署的發行版。可以自行建置（見[建置](#建置)），或從 GitHub Actions 的執行結果下載 debug APK。

## 使用方式

### 產生密碼

1. 從 App 圖示或快速設定方塊開啟。
2. 輸入主密鑰與服務金鑰，密碼會即時顯示。
3. 視需要調整長度（6–75，預設 20）與符號（一個字元，插入在密碼的第 6 個位置）。
4. 點一下密碼，或按鍵盤的完成鍵，即複製並關閉。

長按密碼時，密碼區會交替顯示「放開即複製並關閉」與密碼。放開即複製；手指滑出密碼區再放開則取消。

### 每個服務的設定

複製密碼時，App 會記住這個服務的長度與符號。下次輸入同一個服務金鑰時自動套用，服務金鑰欄會出現循環箭頭圖示。

服務金鑰本身不會被儲存；記錄以加鹽的 HMAC-SHA256 值為索引。

### 儲存主密鑰

主密鑰欄右側的手機圖示是「儲存主密鑰於此裝置」的開關。打開後，下次開啟會直接從服務金鑰開始輸入。

| 欄位狀態 | 意義 |
|---|---|
| 已儲存，欄位留空 | 使用已儲存的主密鑰。App 只有雜湊，所以不顯示圓點，也無法顯示內容。 |
| 已儲存，輸入了內容 | 本次改用輸入的主密鑰。標籤變為「將取代已儲存」，複製密碼時才取代已儲存的。 |
| 關閉開關 | 先確認，確認後刪除已儲存的資料與金鑰。 |

### 生物辨識

裝置支援時自動啟用，可在設定頁關閉。

- 儲存時不需要驗證；開啟 App 時跳出系統的生物辨識畫面，通過後才能使用已儲存的主密鑰。
- 選「改為輸入主密鑰」或取消時，可以直接輸入主密鑰。這只在本次使用，不會覆蓋已儲存的；欄位右側的開鎖圖示可以再次解鎖。
- 鎖定且未輸入主密鑰時，不會產生密碼。
- 新增或刪除指紋後，已儲存的主密鑰會失效並被清除，需要重新輸入並儲存。

### 設定頁

從卡片右上角的齒輪圓鈕進入。

| 項目 | 說明 |
|---|---|
| 預設長度 | 用於沒有記錄的服務，下次開啟產生器時生效。 |
| 以生物辨識保護已儲存的主密鑰 | 變更後，在下一次開啟並解鎖時轉換保存方式。 |
| 禁止截圖 | 回到產生器時立即生效。 |
| 已記住的服務設定 | 顯示數量，可全部清除。 |
| 快速設定方塊 | 請系統跳出「加入方塊」的詢問（Android 13 以上）。 |
| 關於 | 演算法、自我檢查結果、版本。 |

### 警告

警告只改變標籤文字與顏色，不阻擋操作。

| 情況 | 顯示 |
|---|---|
| 主密鑰為空卻產生了密碼 | 標籤變為「主密鑰・空白」 |
| 服務金鑰前後有空白 | 標籤變為「服務金鑰・含前後空白」 |
| 長度在 12 以下 | 長度數字與圖示變色 |

## 與瀏覽器版的差異

以下差異都不影響產生的密碼。

- 服務金鑰為空時不顯示密碼（瀏覽器版會產生一組）。
- 符號欄只接受一個 BMP 字元，emoji 與控制字元會被拒絕（瀏覽器版會插入半個代理對，產生亂碼）。
- 每個服務除了長度，也記住符號（瀏覽器版只記長度）；記錄在複製密碼時寫入。
- 已儲存主密鑰時清空主密鑰欄，代表使用已儲存的主密鑰（瀏覽器版會把空字串的雜湊存起來）。
- 新輸入的主密鑰在複製密碼時才取代已儲存的（瀏覽器版每打一個字就覆蓋一次）；空的主密鑰不會被儲存。

主密鑰為空且沒有已儲存的主密鑰時，仍會產生密碼，這點與瀏覽器版一致，並以標籤提示。

## 安全設計

- **主密鑰**：只儲存 SHA-256 雜湊，不儲存原文。
  - 啟用生物辨識保護時，以 Android Keystore 中的 RSA-2048（OAEP）金鑰加密，私鑰每次使用都需要通過高強度生物辨識。
  - 未啟用時，以 Keystore 中的 AES-256-GCM 金鑰加密。
- **備份**：關閉 `allowBackup`，並以資料擷取規則排除雲端備份與裝置轉移。
- **畫面**：預設禁止截圖與在最近使用的 App 中顯示預覽（`FLAG_SECURE`）。
- **剪貼簿**：複製時標記為敏感內容，系統的剪貼簿預覽不顯示密碼。App 不會自動清除剪貼簿。
- **自我檢查**：App 內建 5 組已知答案，設定頁的「關於」會顯示演算法自我檢查的結果。

## 建置

需要 JDK 17 以上與 Android SDK（API 36）。用 Android Studio 開啟專案資料夾，或在命令列執行：

```
./gradlew :core-lik31:test :app:testDebugUnitTest   # 單元測試
./gradlew :app:assembleDebug                        # 產生 app/build/outputs/apk/debug/app-debug.apk
```

推送到 GitHub 後，`.github/workflows/ci.yml` 會自動執行測試，並把 debug APK 存成 artifact。

無法連線 Maven 時，可用 `tools/run-local-tests.sh` 以 Gradle 內附的 Kotlin 編譯器執行純 Kotlin 部分的測試。

## 專案結構

```
core-lik31/               純 Kotlin 演算法模組（不依賴 Android）
app/                      Android App（Kotlin、Jetpack Compose、Material 3）
docs/                     設計與開發文件
design/                   圖示原稿（依 U+26BF ⚿ 的造型繪製）
tools/gen-vectors/        以 Node 執行瀏覽器版的 popup.js，產生比對資料
tools/run-local-tests.sh  不經 Gradle 相依解析的本機測試
```

## 測試與演算法一致性

單元測試共 83 個。其中 `golden-vectors.json` 有 246 筆比對資料，由未經修改的瀏覽器版 `popup.js` 產生，用來確認兩邊的輸出逐字相同。

瀏覽器套件改版時，以新版覆蓋 `tools/gen-vectors/popup.js`，然後重新產生比對資料：

```
node tools/gen-vectors/gen-vectors.mjs
```

CI 會檢查已提交的 `golden-vectors.json` 與重新產生的結果一致。
